C

Codex

Los hooks no corren hasta que los apruebas. Codex los marca como no confiables: revísalos y acéptalos en /hooks, y repítelo cada vez que el harness los cambie.

El hook está registrado para la herramienta Bash. Si en Windows Codex usa otra, el push no se bloquea: anota el nombre exacto.

A

Antigravity

Vale para la App, el IDE y la CLI. Si el hook corre pero no puede revisar, Antigravity te pregunta en vez de dejar pasar el comando: no lo apruebes y reporta el motivo.

El check automático tras crear un Pull Request no corre aquí. Hazlo a mano:

Comandonode .claude/hooks/reglas-pr.mjs --pr <url-del-pr>
!

Dos casos que no sabemos cómo se comportan. Desde una subcarpeta el hook puede no encontrarse y el push pasaría sin aviso. Y si Codex en Windows ejecuta PowerShell pero lo informa como Bash, un push sin destino explícito puede escaparse. Las pruebas 8 y 9 lo confirman.
