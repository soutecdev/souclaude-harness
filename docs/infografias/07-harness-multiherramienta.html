Codex y Antigravity: en prueba
Harness souclaude · v3.20.0 · SHS-M48

Un harness, tres herramientas de IA

El harness de SOUTEC se instala a la vez para Claude Code, Codex y Antigravity. Esto es lo que cambia, lo que hay que tener en cuenta al instalarlo y cómo probarlo en cada herramienta.

La idea

Una instalación sirve para las tres herramientas, sin preguntar cuál se usa. init y upgrade dejan siempre lo mismo, así que un repo puede trabajarse con una herramienta hoy y con otra mañana, o con varias a la vez. Las reglas del proyecto son las mismas para todas.

Una sola fuente para cada cosa

Instrucciones

CLAUDE.md ↑ remite AGENTS.md

CLAUDE.md sigue siendo el único archivo de reglas, el que cada equipo adapta. AGENTS.md es un puntero: manda a leerlo y explica cómo traducir lo que es propio de Claude Code.

Skills

una skill en el harness ↓ .claude/skills.agents/skills

Las dos carpetas llevan los mismos archivos. Son copias que genera el harness: nadie las mantiene a mano y no pueden quedar desparejas.

Hooks

.claude/hooks/ (la lógica) ↓ Codex: directoAntigravity: adaptador

Las reglas se escriben una vez. Codex usa el mismo formato que Claude Code; Antigravity usa otro, y un adaptador solo traduce.

Al instalar o actualizar

  • Todo repo recibe archivos nuevos en su próximo upgrade: AGENTS.md, .codex/, .agents/ y una segunda copia de las skills, se use o no esa herramienta.
  • Lo que el equipo ya tenía no se pisa. Un AGENTS.md propio queda intacto, con la propuesta del harness al lado en AGENTS.md.new. Los hooks.json propios se conservan y se les suma lo del harness.
  • La carpeta .claude/ tiene que existir aunque nadie use Claude Code: ahí viven los scripts de los hooks y la configuración del harness (vault.local.json, harness.json).
  • Todo se versiona. AGENTS.md, .codex/ y .agents/ van al repo como el resto del harness; el upgrade se integra por rama y Pull Request.
  • Requisitos: Node 22.4 o superior y git. Los hooks se ejecutan con node en las tres herramientas.

Qué hacen los hooks iguales en las tres herramientas

reglas-pr · antes de cada comando de terminal

  • Deniega cualquier git push que toque main.
  • Deniega el push que subiría un archivo de credenciales (.env, llaves, tokens).
  • Un comando normal pasa sin mensajes ni demora.

Inicio de sesión

  • Le recuerda al agente la regla de trazabilidad: todo trabajo pertenece a un milestone del Vault.
  • Le muestra el tablero de milestones en curso, si el Vault está conectado.
Si los hooks no corren, las reglas valen igual. AGENTS.md las repite en texto: nunca push a main, nunca subir secretos. Sin hook, nada lo bloquea: depende de que el agente obedezca.

Lo que cambia al probar cada herramienta

Codex

  • Los hooks no corren hasta aprobarlos. Codex los marca como no confiables: hay que revisarlos y aceptarlos en /hooks, y repetirlo cada vez que el harness los cambie.
  • El hook está registrado para la herramienta Bash. Si en Windows Codex usa otra, el push no se bloquea: hay que anotar el nombre exacto.
  • Al crear un Pull Request, corre el mismo check que en Claude Code.

Antigravity

  • Vale para la App, el IDE y la CLI: los tres leen .agents/hooks.json.
  • El adaptador supone que la terminal en Windows es PowerShell.
  • Si el hook corre pero no puede revisar, Antigravity pregunta en vez de dejar pasar el comando: no lo apruebes y reporta el motivo.
  • No corre el check automático tras crear un Pull Request. Se corre a mano: node .claude/hooks/reglas-pr.mjs --pr <url>.
Dos casos que todavía no sabemos cómo se comportan. Si la sesión se abre desde una subcarpeta, el hook puede no encontrarse y el push pasaría sin aviso. Y si Codex en Windows ejecuta PowerShell pero lo informa como Bash, un push sin destino explícito puede escaparse. Las pruebas 8 y 9 son para confirmarlo.

Las nueve pruebas 30 a 45 minutos por herramienta, en un repo desechable

1Las instrucciones se cargan: ¿leyó CLAUDE.md, y cuándo?
2Las skills aparecen y adr-new se activa.
3it-security-review no corre sola.
4Los hooks figuran registrados y habilitados.
5La sesión nueva conoce la regla de milestone.
6El push a main se bloquea.
7Un secreto no se sube.
8En Windows: qué shell usa la herramienta.
9El push a main se bloquea también desde una subcarpeta.

Las pruebas 6, 7 y 9 son las que importan: son las reglas que protegen main y las credenciales. Paso a paso en docs/pruebas-multiherramienta/.

En qué estado está

Verificado

  • La suite del harness pasa completa (715 tests, 19 nuevos).
  • La instalación deja los archivos de las tres herramientas.
  • El push a main y el push con un secreto se deniegan con entradas simuladas en el formato de Codex y en el de Antigravity.
  • Un upgrade no toca lo que el equipo editó.

Pendiente o fuera de alcance

  • Nada se probó en Codex ni en Antigravity reales: se construyó contra su documentación.
  • Las skills que solo corren a pedido usan un campo de Claude Code; las otras herramientas podrían activarlas solas.
  • Los permisos de Claude Code (por ejemplo, no leer .env) no se trasladan.
  • Los conectores MCP (Jira, Azure Boards) no se registran para Codex ni Antigravity.
